Keep the test secret.
Audit the score.

Sealed Bench runs a sampled audit of an AI benchmark score on a private test set. The set and every graded run are committed on NEAR, a permissionless random draw picks which entries must be opened, and the contract checks each one against the NEAR AI Cloud TEE signature on its response.

The problem

A public benchmark is a leaked exam.
A private one is a promise.

A

Public sets leak

Test questions end up in training data. A high score can mean the model learned the skill, or that it saw the answers.

B

Private sets can't be checked

Keep the questions secret and the leak stops, but now the score is just someone's word. Nobody outside can audit it.

C

Sealed Bench does both

The set stays private. After every run is committed, a random sample is opened and checked by a contract. Misreport 10% of entries and a 20-of-100 sample catches it about 90% of the time.

Result

Public originals vs. sealed variants.

Same 25 GSM8K problems: the public originals, and 100 private numeric variants (4 per problem), never published; only the NEAR AI TEE inference saw them, and the 20 sampled ones are now public. Temperature 0. A large gap would hint at memorization; these two models show none. GSM8K is easy for both, so this is a ceiling result, not evidence for or against contamination.

Tamper lab

Try to cheat.
The contract is listening.

Each attempt goes to the real contract's check_reveal view, a free read-only call that runs the same checks as a reveal and reports the first one that fails (usually a Merkle proof). Nothing is written on-chain.

The math

Twenty draws.
Probabilistic, not perfect.

A misreport survives only if the 20-of-100 sample misses every bad entry. Big lies rarely survive; small ones often do. Inflating 98 to 100 (2 entries) is caught only about 36% of the time, and an owner who retries 10 suites at 10% misreporting gets one through about 63% of the time. Drag to see the odds.

Per run, exact hypergeometric odds for 20 distinct entries out of 100. This is not the probability the score is correct, and it says nothing about benchmark quality.

Built on NEAR

The checks run on-chain.
The trust list is below.

TEE-signed inference

Models run in Intel TDX + NVIDIA confidential VMs on NEAR AI Cloud, which signs each response with a key held inside the attested enclave. The signature covers the gateway's model id, not the weights.

GET /v1/signature/{chat_id}
// signs, EIP-191 personal_sign:
"MODEL:" + sha256(request) + ":" + sha256(response)

On-chain ecrecover

The contract rebuilds the exact request bytes, hashes both sides and recovers the signer itself.

// contract/src/verify.rs
let pk = env::ecrecover(&hash, &sig[..64], v, false).ok_or("ecrecover failed")?;
let h = env::keccak256_array(&pk);
// contract/src/lib.rs
let pinned = self.signers.get(&run.model).cloned().unwrap_or_default();
if !pinned.iter().any(|p| p.address == addr) {
    fail!("signature not from a pinned signer for {}", run.model);
}

Chain randomness, twice

random_seed sets each run's nonce, and draws the shared sample once every run is committed. The draw is permissionless: anyone can trigger it.

Attested signers

The admin pins each signer after checking its TDX quote off-chain with dcap-qvl. The report's sha256 is stored on-chain with the pin.

Free verification

The check_reveal view runs the reveal checks for free over RPC. This page uses it, and so can you.

Threat model

What you trust, what it proves,
and what it doesn't.

You trust

  • NEAR AI Cloud's TEE signing key for each model. The inference provider sees the sealed entries, inside the TEE.
  • The admin who pins a signer after verifying its attestation off-chain (DCAP quote, report-data binding, MRCONFIGID, RTMR3 replay).
  • The model id, which is the gateway's claim. The signature authenticates that claim, not the weights.
  • The upgrade authority. The contract account holds a full-access key and has been redeployed with state kept, so results are only as permanent as that key until it is locked.
  • Shared keys: instances of one model share a signer, so a match doesn't name the serving instance.

It proves

  • Revealed items were fixed before the run.
  • Each revealed response was produced for this run's nonce and signed by the pinned TEE key.
  • Committed grades match a deterministic re-grade of the raw bytes.
  • The score is the sum of the committed grade vector.

It doesn't prove

  • Unsampled entries. Checked only probabilistically, under the bound above.
  • Re-rolls. The per-run nonce stops answers made before the run, not best-of-N re-rolls within it. Temperature 0 makes re-rolls less useful; it doesn't prevent them.
  • Small lies. Detection is probabilistic: about 90% at 10% misreported entries, about 36% for a 2-entry inflation. Retrying across suites raises the odds of slipping through.
  • Secrecy from the owner. The set is hidden from vendors and the public, not from its owner.
  • An unbiased draw. Block producers can slightly bias random_seed. The draw is permissionless, but in these runs the operator's own admin account called it, and the v1 contract lets the caller batch the draw with reveals and retry. Both are being fixed in v2.

Also: each reveal spends 20 items of the sealed set. The 0.1 NEAR testnet bond is locked, not slashed. The DEV-ONLY mock signer uses a public key, is labeled mock/DEV-ONLY-not-a-TEE, and no claim cites it.

Verify it yourself
in about two minutes.

No NEAR account, no wallet, no API key. Node 22.18+ and network access to testnet RPC.

  1. Replay the real audits. Re-derives the challenge from the chain seed, replays every reveal offline, then checks roots, grades, signers and check_reveal on-chain.
  2. Try to cheat. Nine edits to a real TEE-signed entry. All nine rejected, each with the reason the checks give.
~/sealed-bench 
$ git clone https://github.com/jazulay/sealed-bench
$ cd sealed-bench && npm ci

$ npm run verify
# expect "ok": true and 4 results (2 suites × Qwen, GLM)
# every check true · "onchain_status": "Audited"

$ npm run tamper
# expect "9/9 lies rejected; honest reveal accepted=true"
